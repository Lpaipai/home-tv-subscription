# LWP 家庭影音订阅

**家庭精选当前包含 33 条经过短时音视频输出检查的线路。** 独立订阅入口为 `public/family-preview.m3u`，`live.m3u` 第一组同步展示同一批线路；其余分类保持原有规则。33 是当前数量，不是上限。订阅内容更新后，支持该格式的播放器可刷新目录。CCTV-14、15、17 的测试样本为测试卡，解码输出通过不代表节目内容正常或长期稳定。

这是我们自己维护的频道与点播配置目录。播放器从订阅取得地址，再访问上游；本项目不托管视频，未取得或提供 HTV 的完整内置源。

## 使用入口

- 影视仓多仓：`https://raw.githubusercontent.com/Lpaipai/home-tv-subscription/main/public/subscription.json`
- mytv 直播：`https://raw.githubusercontent.com/Lpaipai/home-tv-subscription/main/public/live.m3u`
- 影视仓直播：`https://raw.githubusercontent.com/Lpaipai/home-tv-subscription/main/public/live.txt`
- 家庭精选独立目录（M3U）：`https://raw.githubusercontent.com/Lpaipai/home-tv-subscription/main/public/family-preview.m3u`
- 人工画面对照版：`https://raw.githubusercontent.com/Lpaipai/home-tv-subscription/main/public/family-content-checked.m3u`（可能仅有少量频道）

这是同一个维护项目下的两个格式入口：M3U 负责直播，JSON 多仓负责点播，不能把点播站点直接拼进 M3U。

## 投影仪怎么用

- 直播：mytv 选 `LWP 家庭直播`；影视仓的直播菜单 → 直播地址 → `LWP 家庭直播`。
- 点播：影视仓首页 → 配置 → `LWP 家庭影音` → `王二小`。首页按遥控器菜单键选择 `葵花┃影视`，再进入电影或电视剧分类。当前订阅已把这个站点排在王二小配置首位。
- 影视仓停留在直播时，按菜单 → 退出直播，回到点播首页。初次加载播放组件可能较慢；加载卡住时按一次返回可跳过加载，再切换线路或配置。
- 网页显示推送成功后，还要在电视端选中新增项目。海报首次点按可能只移动焦点，再按遥控器确认键才进入详情。
- 豆瓣推荐、分享说明页不直接提供视频；网盘类入口可能要求用户自行登录。

实测记录见 [VERIFICATION.md](VERIFICATION.md)。当前有可用样例，不代表每个来源和每部影片均可播放。

| 文件 | 用途 |
|---|---|
| `public/subscription.json` | 影视仓多仓总入口：从一个地址切换各点播仓库 |

| `public/source-review.json` | 三个社区候选源的发现统计；未测地址只公开线路标识和网络类型 |
| `public/candidate-health.json`、`public/candidate-health-history.json` | 候选源小样本实播结果、自动收录数量和历史分；通过后进入正式源抽检 |
| `public/live.m3u` / `live.txt` 中的 `家庭精选` | M3U 首组与固定精选一致；TXT 无法无损携带请求头时不写入该线路 |

| `public/auto-additions.json` | 自动收录与跨日历史：视频解码通过为 `video_decoded`；显式许可来源的公网 IPv6 作为 `ipv6_unverified` 备用线路发布，不伪造成功记录 |

| `public/family-review.json` | 家庭线路人工核验待办清单：近期解码、节目身份、网络地址类型 |

影视仓各单仓保留原有 `spider`、`sites`、解析器与规则，统一注入家庭直播入口；不把依赖不同插件的站点生硬拼成一仓。嵌套多仓递归整理；无法读取的子仓仍保留原地址，并标记失败。配置搬迁时，以原作者配置地址而非镜像目录为基准修正相对路径。

## 频道分类与候选检测

- `家庭精选` 当前包含 CCTV、CGTN 和卫视，后续可按验证结果新增其他频道及分类；独立目录保留每台的分类。
- 分组和组内排序遵循频道规则，展示顺序不额外占用检测名额。
- 候选来自公开频道列表，普通线路每日最多首测 12 条播放地址，按有限额轮换检测。显式授权来源中的公网 IPv6 字面量按独立待验证规则发布，不占这 12 条云端检测预算。
- 音频源不能作为电视源收录；短时视频解码不代表节目身份、家庭网络可用性或转播授权已验证。
- 原 `live.m3u` 和 `live.txt` 入口保持不变。

## 自己维护

频道名称和分组规则保存在 `channel_names.json`、`channel_catalog.py`。修改后运行 `python -B update.py --cached` 即可用已保存的上游目录重新生成；以后更新上游时同样自动应用规则。

- 分组顺序：央视、卫视、地方、国内其他、国际、香港、台湾、美国、日本、韩国。教育、CHC 等全国性非央视频道放在国内其他。
- 央视主频道按数字排序，5+ 位于 5 后面；其他频道按名称排序，中文常用字采用 GB18030 顺序。
- 去除显示名中的清晰度、地区限制和非全天标记，常用频道改为中文；原始名称与分组仍保存在本地 `state/live_entries.json`。没有可靠对应名称的台保留原名。
- 同一频道的不同地址连续输出、使用相同显示名，让支持合并的播放器显示成多条线路。节目不同的东、西部版保留区别。地址、请求头和上游节目单 ID 保持原值。
- `public/channels.json` 列出各频道的线路数，不能把只有一条地址的频道视为具备备用线路。
- 自动换源由播放器执行，订阅文件本身不能计时、检测卡顿或识别错误节目。mytv 启用同名频道合并并设置加载超时；影视仓使用直播菜单中的“超时换源”。

1. 在 `config.json` 调整直播目录或点播多仓入口。
2. 使用 Python 3.10 或以上运行：`python -B update.py --base-url https://你的托管地址`。
3. 运行 `python -B -m unittest -v test_update.py`。
4. 查看 `public/status.json`，再发布整个 `public` 目录，保留相同 URL。

本仓库已经配置上述固定地址，手动执行 `python -B update.py` 可同时更新直播和点播；检查后使用 Git 提交并推送。只调整托管地址时可用 `--cached` 重新生成，保留缓存的原始获取时间。直播定时维护见下节。

`preferred_vod` 调整点播入口顺序；`vod_home_api` 设置实测优先站点；`live_exclusions` 保存内容不符线路的地址、原始名称与排除理由；按 URL 跨来源排除。上游新增或失效不会自动等同于实播通过。手动运行脚本后需提交与推送，播放器才会读到新目录；Actions 成功运行时自动提交发布。

## 家庭精选与候选自动收录

- **家庭精选已经在原 `live.m3u` / `live.txt` 的第一个分类中展示。** “试用”仅表示没有逐条人工确认节目和长期稳定性；电视不需要添加新入口。
- `candidate_sources.json` 读取 fanmingming、Guovin 等九份公开候选列表。新地址先暂存在忽略目录 `state/candidate_entries.json`，发现报告只公开未测地址的指纹。
- 候选普通线路使用 `decode_then_publish`：每天首测最多 12 条，失败复测最多 4 条；**本轮最终成功解码至少 3 个视频采样帧且未被错台规则拦截的地址，自动加入原来的正式频道分类**。**例外：仅 `candidate_sources.json` 明确启用 `ipv6_direct_publish` 的来源，其公网 IPv6 字面量 URL 可不经云端 FFmpeg，直接以 `ipv6_unverified` 状态加入原订阅，作为待家庭验证的备用线路。** 当前先为 fanmingming IPv6 来源启用，每次最多新增 128 条；绝不接受回环、私网、链路本地、映射 IPv4 或带危险播放参数的地址。同名频道作为备用线路，家庭精选按原有规则更新。不再等待人工确认，不要求用户逐条审核；未测、失败、受限和跳过的候选不自动加入。
- 经视频解码的地址与来源、检测时间保存到 `public/auto-additions.json`，标记 `admission: video_decoded`；免云端检测的公网 IPv6 标记 `admission: ipv6_unverified`，不填写虚假的成功时间。每日目录更新会重新合并这些线路；新增到期复检流程，正常或重新解码成功会自动续期，已停用的线路解码成功后也会自动恢复。
- **自动线路生命周期**：首次成功后第 7 天进入复检队列；每天额外最多复检 8 条、失败最多复测 2 条；至少间隔 2 天才重试同一未停用线路。只有**距最后成功解码 ≥14 天且至少两个不同 UTC 日期解码失败**，才标记 `suspended` 并暂时从订阅中移除。没有轮到检测、仅受限或跳过都不会因为时间到了直接删除；被暂停的线路间隔至少 7 天仍尝试复活。正式抽检里新近成功的线路会自动续期。
- **复检公平轮换**：在用与停用线路默认各保留 4 个名额，某类不足时另一类可用剩余额度；各类内部优先选择最久未尝试的地址。缩小为奇数预算时，额外名额按 UTC 日期交替。持续受限或失败的老线路不会反复挤掉其它到期线路。
- **低成本 OCR**：候选短时解码通过后，最多挑 3 条央视/部分卫视候选临时获取 2 帧画面，对左上角做本地 Tesseract OCR；两帧都读出相同的其他频道时才标记 `mismatch` 并跳过本轮自动收录。读不清、画面没有文字台标、缺乏模板或预算不足标记 `unknown`/`unsupported`/`not_checked_budget`；无既有错台记录时按解码通过规则继续收录，**不能宣称这些线路已核实频道身份**。CCTV-5 与 CCTV-5+ 如 '+' 不清晰，宁可未知也不武断判错台。截图只放在临时目录，检查结束即清理，不上传仓库。OCR 免费但覆盖有限，尤其卫视图形 Logo 难以 OCR。
- **错台记录跨轮保留**：`candidate-health-history.json.visual_holds` 按线路标识保存疑似错台，独立于滚动健康历史清理；即使下一轮 OCR 没轮到、读不清或工具缺失，也继续拦截。被拦截且本轮解码通过的候选优先分配 OCR 名额，重新识别为 `match` 后自动解除，无需人工逐条确认。新候选没有错台记录时，OCR 未知仍按解码通过规则收录。OCR 安装失败或超时只写运行摘要，继续维护订阅，不扩大探测预算。
- 自动收录不等于已经确认台标、节目、声音、家庭网络或长期稳定性；尤其 `ipv6_unverified` 只证明地址来自明确允许的公开列表、且 URL 是公网 IPv6，不代表在电视端已验证。用户发现错台或异常后提供频道及对应线路信息，将 URL 加入 `config.json.live_exclusions`，后续发现、收录和重新生成都会排除它，不因名称变化再次加入。
- 云端只解码其网络可达的 HTTP(S) 地址及支持的请求参数；显式 IPv6 仍跳过 GitHub 云端检测且不扣分，但明确获准的**公网** IPv6 会以未验证备用线路进入 `live.m3u` 与 `live.txt`；其他 IPv6 和所有私网地址不会绕过发布门槛。待验证 IPv6 不参与自动复检、失败扣分或暂停，直到将来取得真实实播证据。**能在电视频道列表中看到不等于能播放：家庭宽带、路由器与播放器需要 IPv6 连通，频道身份和播放授权均未验证。**M3U 保留特殊请求头；TXT 无法无损表达这类参数时继续跳过该条，避免发布无法正确播放的转换结果。
- 发布前在临时目录完成播放列表、精选、数量和来源记录；出错时保留上一版。候选发现或检测失败不阻断原有正式目录维护。
- `family_selection.json` 当前使用 `mode: fixed` 和 `fixed_entries` 维护这 33 条精确线路及请求头，每台 1 条。云端重生成只读取这份清单，不以旧源池或新候选替换精选；维护此文件即可在固定订阅入口更新、替换或删除线路。新增频道时同时加入 `channels` 和 `fixed_entries`，在条目的 `group` 中填写分类；经回归检查和工作流发布后，播放器刷新原订阅即可取得目录变更。33 不作为生成器或回归的固定数量限制。旧 `health_ranked` 模式仍保留供显式切换，当前未启用。原分类仍保留。`family-content-checked` 只包含最近 21 天人工核对过画面的地址；自动解码成功不会被标成“人工确认”。
- Guovin 示例分支可能较旧，仅以本次实际解码结果决定收录。使用公开列表数据，未复制其 AGPL 源码；目录中的 CCTV、CGTN、NHK 网页只是观看页面，不当作直播 M3U API。

## 免费定时维护

入口：[GitHub Actions 维护任务](https://github.com/Lpaipai/home-tv-subscription/actions/workflows/maintain.yml)。订阅地址不变，电脑无需开机，播放器需刷新订阅。

| 任务 | 北京时间 | 范围和限额 |
|---|---|---|
| 更新直播目录 + 重点频道实播抽检 | 每天 06:23 | 13 个正式上游目录（含 Nexus 六个地区），候选解码通过自动加入原订阅；更新步骤最多 5 分钟；随后首测最多 24 条（央视/卫视占 75%），失败复测最多 8 条；检测步骤最多 4 分钟 |
| 全目录轮换抽检 | 每周日 07:23 | 首测最多 120 条（央视/卫视占 50%），失败复测最多 40 条，4 路并发，每次最长 16 秒，抽检步骤最多 13 分钟 |

另外每天尝试获取 9 份候选文本并更新匿名摘要（限时 2 分钟），再对候选执行最多 16 次有限额探测、最多 3 条临时截图 OCR，并按解码结果自动收录（步骤限时 3 分钟）；之后独立复检最多 8 条已自动收录线路及 2 次失败复测（步骤限时 3 分钟）。发现、OCR 或复检失败不阻断正式直播维护。工作流采用公开仓库的标准 `ubuntu-24.04` 运行机器，每次任务总上限 20 分钟。转为私有仓库后自动跳过任务。无付费 AI、无大规格机器、无视频或截图产物上传；仅缓存上游文本，并覆盖发布小型 JSON/Markdown 报告。运行时间免费遵循 [GitHub 当前计费规则](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。不修改账户付费设置。

定时触发可能延迟；公开仓库长期无活动可能被 GitHub 暂停定时任务。可在 Actions 页面通过 `Run workflow` 手动选择 `update` 更新或 `scan` 抽检，并检查运行状态。

自动更新启用 `--live-only --guarded`，且不会自动刷新点播配置：有来源失败且没有缓存、全部来源仅有旧缓存、总线路减少超过 20%、任一来源条目减少超过 40% 时停止发布，远端上一版保持不变。少量来源失败但有缓存时会沿用缓存，并在 `public/status.json` 标注。Git 推送遇到人工并发提交时会失败，不强制覆盖。

每日小样本抽检优先覆盖央视/卫视（18 条配额），并按天轮换；每周抽检保持一半配额给央视/卫视、其余覆盖其他频道。抽样先覆盖不同频道，再选同频道备用线路，并优先选择未检测或最后尝试时间最早的线路。受限和跳过也记录尝试时间以让出轮查机会，但不修改解码证据时间或扣健康分。同地址同请求头只测一次。每日实播步骤偶发失败不会中断通过发布门槛的目录更新，Actions 摘要会说明该次未完成抽检，保留上次报告。使用 FFmpeg 尝试获取 4 秒视频并要求成功解码至少 3 个采样帧；不支持的特殊播放参数明确跳过。结果见 [抽检报告](public/health.md) 和 `public/health.json`，在首次抽检成功后生成。

抽检只是云端短时视频解码验证；显式 IPv6 地址跳过、不扣健康分。不验证声音、节目身份、广告、长时间卡顿或家庭网络可用性；失败线路不会自动删除。已有人工识别的购物广告黑名单继续生效。没有声称每周全量检测。

本地验证命令：`python -B -m unittest -v`。新增维护逻辑依赖本项目的频道分组、发布目录和人工规则，未形成独立通用功能单元，本次不复制到复用库。

工具只使用 Python 标准库，无需安装依赖。更新失败时使用该来源最后一次通过解析的缓存，保留原始获取时间；所有直播来源失败且无缓存时停止生成。每次成功发布前，上一份本地结果保存在 `backups`。第一次运行没有缓存的失败源会明确标记，不声称已成功导入。

`cache`、`state`、`device`、`backups` 为本机工作与验证数据，不上传。设备备份可能包含个人设置，应保留在本机。

## 来源与验证边界

- 直播：iptv-org 大陆、香港、台湾、美国、日本、韩国目录；Lightconer 国内备用；[IPTV Nexus](https://github.com/dearbulut/iptv) 同六个地区的完整 streams API。
- 点播：Lightconer/tvbox-ysc-config 多仓订阅，保留各原作者名称与来源。
- HTV 完整内置源没有获得，不纳入本项目。

目录能下载、JSON 能解析、插件校验和一致，与节目实际播放是不同结论。`status.json` 的条目数不是可播放数量。动态插件仍由原站提供，本工具不执行插件，也没有完成其代码安全审计。上游失效、网络地区差异、播放器兼容性均可能影响使用。

采用局域网临时托管时，电脑需开机且投影仪位于同一网络。长期使用应部署到确认过的托管位置；公开托管会让目录中的频道地址和点播配置公开可见。

公开上游目录及插件保留各自权利与使用条件；本项目不对上游内容作许可或稳定性保证。

`live_additions` 保存经过人工画面对照的补充线路；每条记录来源与核验日期。它们仍需定期复核，并不保证长期有效。

## 数量说明与回退

- `status.json.auto_additions_ipv6_unverified` 统计通过明确来源白名单进入正式订阅、但仍未经实播验证的 IPv6 备用线路数；云端抽检不会将它们误计为成功。\n- `status.json.live_entries` 统计的是去重后的**原有正式线路**数量，不含家庭精选重复展示；`status.json.published_live_entries` 才是 M3U 文件中的实际 `#EXTINF` 条数（含精选分组）；`family_lines` 表示精选额外显示的线路数。
- 若云端更新失败，现有发布门槛会停止覆盖上一份 `public`；候选源异常不会影响主订阅。固定模式下同步清空 `family_selection.json.channels` 与 `fixed_entries` 会取消精选分组，仍保留其他原始频道。播放器端无需更换订阅 URL。
- 使用本地 OCR **尝试**识别部分频道画面左上台标，但不能识别所有图形台标、广告或完整节目；不把截图持久化、不上传截图，也不将网页直播地址伪装为官方开放 M3U API。按用户选择，来源 `rights: unverified` 暂不作为自动发布阻断条件；这不表示取得授权。

## Nexus 来源与历史评分

采用 Nexus 的多来源归并、历史健康分与备用线路排序思路，使用本项目 Python 标准库实现，没有部署其 Node 服务或引入付费服务。

- 每天读取 Nexus 六个地区的国家 API，保留每个频道的全部公开 streams，不只取其推荐的一条。其他国家未全量导入。
- 相同台标 ID 对齐已有名称；保留地区、东/西部版和播放请求头。相同频道、地址及参数去重，并合并来源。上游的 online 标签不算本项目解码通过，也不据此删除其 offline 候选。
- `public/line-origins.json` 按线路标识记录地址和来源列表；`public/status.json` 的 `nexus_unique_lines` 是仅由 Nexus 提供的不同地址/参数组合数量，不是可播放数量。
- 每日最多 24 条首测、8 条失败复测，总探测不超过 32 次；每周最多 120 条首测、40 条失败复测，总探测不超过 160 次。复测成功以最终成功记一次；连续失败次数按维护轮次计，不把一次首测及复测失败算两轮。
- `public/health-history.json` 保存每条线路最近 30 次云端观测；评分按旧分 70% 加本次结果 30% 更新，成功记 100、普通失败记 0、初始 50。401/403/429/451 和不支持的播放参数不扣分。
- 同频道内优先放最近 21 天解码通过的线路，其次未验证/单次失败线路，最后是连续至少两轮失败的线路；同档已测线路参考历史分。证据超过 21 天恢复中性，后续成功清零连续失败。所有备用线路保留。
- 更新目录和抽检都会应用排序；历史跨 Actions 运行保存在 Git 中。云端排序不代表家庭网络排序，也不会修复失效的上游视频服务器。

已有广告错标黑名单现按地址生效，换名称或从 Nexus 重新出现也会被排除。新增线路尚未逐条核对台标、节目和广告，仍需人工复核；普通电视节目中的合法广告也不等于错标频道。
